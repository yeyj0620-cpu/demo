# 舆情全链路智能处置工作台 · 技术方案

> 版本：v1.0　·　配套《产品设计文档》　·　核心决策已定，本文档只讲「怎么做」

---

## 1. 技术选型（已定）

| 层 | 选型 | 理由 |
|---|---|---|
| 后端 | **Python + FastAPI** | 能写 `/api/*` 代理保护 Key，托管前端，部署门槛低 |
| 前端 | **原生 HTML / CSS / JS** | 无构建工具、无 npm，简历项目足够，改动即生效 |
| AI | **DeepSeek（deepseek-chat）** | 真实大模型，后端代理调用 |
| 持久化（留痕） | **浏览器 localStorage** | Render 免费版磁盘是临时的，SQLite 重启就丢；留痕是「个人本地记录」，放浏览器最合适 |
| 部署 | **Render（免费版）** | 用户有 GitHub、无 Vercel；Render 免绑卡、一键连仓库部署 |
| 数据源 | **RSS 真实新闻**（36氪/少数派/爱范儿） | 弱采集，只做真实数据入口 |

> 为什么不用 SQLite：Render 免费实例磁盘**每次重启都会清空**，SQLite 文件存不住。
> 留痕本质是「本次处置过程的个人记录」，放 localStorage 反而更简单、零后端依赖、不丢（换浏览器才丢，可导出 .md 备份）。

## 2. 架构总览

```
浏览器（静态页面 static/）
   │  用户点击「核查 / 评论 / 投诉 / 报告」
   │  fetch('/api/deepseek', {prompt})
   ▼
FastAPI 后端（main.py）
   │  1. 从环境变量读 DEEPSEEK_API_KEY（绝不写死在代码）
   │  2. 拼 prompt → 调 DeepSeek 官方接口
   │  3. 把结果原样返回前端
   ▼
DeepSeek API（api.deepseek.com）
```

- **Key 只在后端**：前端永远拿不到 Key，前端只发「prompt」。
- **留痕只在浏览器**：处置记录写 localStorage，后端不存任何用户数据。

## 4. 后端接口设计（main.py）

| 方法 | 路径 | 作用 | 返回 |
|---|---|---|---|
| GET | `/` | 返回 `static/index.html` | HTML |
| GET | `/api/status` | 前端探测 Key 是否已配置 | `{"deepseek": bool, "source": "env"/"file"/null, "masked": "sk-***"}` |
| POST | `/api/key` | 在界面里保存/清除 Key（写 `key.txt`） | `{"ok": true, "deepseek": bool}` |
| POST | `/api/import` | 接收二进制上传的 .xlsx，解析舆情条目 | `{"ok": true, "items": [...]}` |
| POST | `/api/deepseek` | AI 统一代理入口 | DeepSeek 原始 JSON |

### `/api/deepseek` 请求体（前端统一格式）

```json
{
  "task": "verify | comment | complaint | sentiment",
  "payload": { "...该任务需要的字段..." }
}
```

> 后端根据 `task` 拼好对应 prompt 再调 DeepSeek，**前端不写 prompt**——
> 这样「prompt 逻辑」集中在后端，前端只是传业务字段，改提示词不用动前端。

### Key 读取优先级

```
环境变量 DEEPSEEK_API_KEY  →  本地 key.txt（已 gitignore）
```

- 都没有 → `/api/status` 返回 `deepseek: false`，前端进入「引导配 Key」状态。
- 页面右上角 Key 徽标可点开，直接在界面里保存/清除 Key（写入本地 `key.txt`）。
- 环境变量 Key 优先级更高，此时界面里显示「已通过环境变量配置」，禁止在界面修改。

### 舆情导入（Brandwatch mentions .xlsx）

- 前端用 `<input type="file">` 选文件后，以二进制 `fetch` 上传到 `/api/import`（Content-Type: application/octet-stream，后端 `request.body()` 直接读，**不引入 python-multipart**）。
- 后端用 `openpyxl`（read_only、data_only）解析第一个 sheet，按表头名映射到归一化字段：情感属性 / 标签列 / 序号 / 品牌类别 / 北京时间 / Title / Snippet / Url / Domain / Sentiment / Emotion / Page Type / Language / Country / Author。
- 跳过整行为空的行；保留「无关」条目但前端默认隐藏（可取消勾选查看）。
- 前端情感口径：人工「情感属性」优先，回退英文 `Sentiment`（positive/neutral/negative → 正面/中性/负面）。

## 5. 前端逻辑（static/app.js）

### 5.1 启动流程

```
页面加载
  → fetch('/api/status')
      ├─ deepseek: true  → 正常模式，可点各模块
      └─ deepseek: false → 顶部常驻提示「请配置 DeepSeek Key」+ 配 Key 弹窗
```

### 5.2 五个模块对应的一次 AI 调用

| 模块 | task | 前端传的 payload | DeepSeek 返回 |
|---|---|---|---|
| ① 采集 | `sentiment` | 一批新闻标题 | 情感数组（负面/中性/正面） |
| ② 核查 | `verify` | 标题 + 内容 | JSON：verdict / risk / evidence[] / conclusion |
| ③ 事实评论 | `comment` | 事件 + 风格 | 一段评论文字 |
| ④ 投诉处置 | `complaint` | 投诉文本 | JSON：type / priority / dept / reply |
| ⑤ 报告 | （纯前端拼装） | — | 汇总前面几步 + 留痕，导出 .md |

> 情感判定失败时：降级关键词规则，并在 UI 上**明确标注「规则判定」**（不冒充 AI）。

### 5.3 留痕（localStorage）

- 存储 key：`handling_log`
- 结构：`[{ ts, module, input, result }...]` 数组，每次处置成功追加一条
- 报告模块读取该数组拼成 Markdown；「导出 .md」用 Blob 下载
- 「清空留痕」只删这个 key

## 6. 部署方案（Render）

### 6.1 步骤（用户有 GitHub）

1. 把 `demo1.0/` 推到一个 GitHub 仓库（**确保 key.txt 已 gitignore，别提交真实 Key**）
2. Render 控制台 → New → Web Service → 连该仓库
3. Render 自动读 `render.yaml`，或手动填：
   - Build Command：`pip install -r requirements.txt`
   - Start Command：`uvicorn main:app --host 0.0.0.0 --port $PORT`
4. 在 Render 的 **Environment** 里加变量 `DEEPSEEK_API_KEY = sk-xxxx`
5. Deploy → 得到公开 URL（如 `xxx.onrender.com`）

### 6.2 免费版注意事项

- 冷启动 30–60 秒（首次打开慢，属正常）
- 15 分钟无访问自动休眠
- 磁盘临时 → 所以留痕用 localStorage，正好避开这个坑

## 7. Key 安全（硬约束）

- ✅ Key 只放两处：Render 环境变量（生产）、本地 `key.txt`（开发，已 gitignore）
- ❌ 不写进 `main.py` / `app.js` / 任何会提交到 GitHub 的文件
- ❌ 打包分享时**永远不把 key.txt 打进去**
- 分享/演示给别人时，对方在 Render 填自己的 Key，或本地放自己的 key.txt
